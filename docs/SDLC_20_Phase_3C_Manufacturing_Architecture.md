# Phase 3C: Advanced Manufacturing Architecture (ERPNext Comparison)

This document maps out the Manufacturing module for HRT Systems. As requested, we have analyzed the architecture of **ERPNext** (a leading open-source ERP by Frappe) to ensure our approach is competitive, while strictly adhering to the HRT Systems Accounting Kernel invariants.

## 1. Architectural Comparison: HRT Systems vs. ERPNext

ERPNext utilizes a "DocType" metadata architecture (similar to Salesforce objects) where everything is tightly coupled. HRT Systems utilizes a highly decoupled **Event-Sourced Accounting Kernel**.

| Feature | ERPNext (Frappe) Approach | HRT Systems Approach |
| :--- | :--- | :--- |
| **Data Model** | Flat DocTypes (e.g., `BOM`, `Work Order`). Flexible but can lead to bloated schemas. | **Strict Relational EAV:** `Source Object` -> `Business Event` -> `Accounting Event`. Guaranteed immutability. |
| **Accounting Integration** | Stock Entries directly hit the GL `tabGL Entry` table. | **Decoupled:** Manufacturing events only create `business_events`. The internal rules engine calculates the exact Debits/Credits for the `ledger_entries`. |
| **Dimensions** | Hardcoded Cost Centers and Projects on line items. | **Dynamic Dimensions:** A Work Order inherits the `DimensionSetID`, dynamically tagging the manufacturing run to any custom dimension (e.g., `Shift_ID`, `Machine_ID`). |

## 2. Core Manufacturing Objects (The Data Plane)

To build a Tier-1 manufacturing system, HRT Systems requires the following core entities:

### A. Bill of Materials (BOM)
The recipe. Defines the Raw Materials, Packaging, and Operations (Labor/Machine time) required to produce one unit of a Finished Good.
*   **Support for Nested BOMs:** A finished good (e.g., a Car) contains sub-assemblies (e.g., an Engine), which has its own BOM.
*   **Version Control:** BOMs must be versioned. If a recipe changes, historical Work Orders must still link to the old version for accurate audit costing.

### B. The Work Order
The execution command. Instructs the shop floor to produce *X* units of a Finished Good by a specific date.
*   It automatically reserves/allocates raw materials in the Inventory Subledger.

### C. Job Cards & Routing
Tracks the actual physical time spent on the shop floor. E.g., 2 hours on the Cutting Machine, 1 hour on the Assembly Line. This is critical for capturing accurate Overhead costs.

## 3. The Accounting Event Matrix (Manufacturing)

To integrate this module into the HRT Accounting Kernel, we must map out the specific `Accounting Events` generated by the shop floor.

### Event 31: `RawMaterialsConsumed` (WIP Transfer)
*When raw materials are physically pulled from the warehouse and moved to the factory floor.*
*   **Source Object:** `StockEntry (Material Transfer for Manufacture)`
*   **Debit:** Work In Progress (WIP - Asset)
*   **Credit:** Raw Materials (Asset)
*   **Accounting Rule:** Moves value but does not impact the PnL.

### Event 32: `ManufacturingOverheadAbsorbed`
*When Job Cards are submitted, calculating the cost of labor and machine electricity used during production.*
*   **Source Object:** `JobCard` / `Timesheet`
*   **Debit:** Work In Progress (WIP - Asset)
*   **Credit:** Applied Factory Overhead (Contra-Expense / Clearing)
*   **Accounting Rule:** Capitalizes operational costs into the physical product.

### Event 33: `FinishedGoodsReceived`
*The critical culmination event. The Work Order is completed, and the final product is placed into the saleable warehouse.*
*   **Source Object:** `StockEntry (Manufacture)`
*   **Debit:** Finished Goods (Asset)
*   **Credit:** Work In Progress (WIP - Asset)
*   **Accounting Rule:** Clears the WIP account. The new Finished Good is valued at exactly (Raw Materials + Absorbed Overhead).

### Event 34: `SubcontractingTransfer`
*When you send raw materials to a 3rd party vendor to assemble on your behalf.*
*   **Source Object:** `DeliveryNote (Subcontracting)`
*   **Debit:** Inventory with Subcontractor (Asset)
*   **Credit:** Raw Materials (Asset)
*   **Note:** When the vendor returns the finished good, it triggers an AP Bill for their labor, plus Event 33 to create the Finished Good.

## 4. Why HRT Systems' Architecture is Superior
While ERPNext is excellent, the HRT Systems architecture is designed for enterprise scale:
1.  **Zero Variance Costing:** Because of our strict `BUSINESS EVENT -> ACCOUNTING EVENT` pipeline, a floor worker cannot accidentally "break" the accounting. They just click "Complete Work Order," and the engine guarantees the WIP clears mathematically.
2.  **Centralized Control Plane:** If Radical TG discovers a bug in how standard costing is calculated, you can deploy a fix via the **Control Plane** instantly to all manufacturing tenants without version drift.
